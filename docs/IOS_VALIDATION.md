# iOS validation and profiling

The iOS port can be configured only on macOS with Xcode and the Apple SDKs. The Windows-side audit validates source structure, ownership, CMake preset syntax, and platform-independent logic, but it cannot validate Objective-C++, Metal, signing, device memory limits, or runtime behavior.

## Build matrix

Generate all three Xcode configurations at least once:

```bash
cmake --preset ios-xcode-debug \
  -DUNLEASHED_RECOMP_IOS_DEVELOPMENT_TEAM=YOURTEAMID \
  -DUNLEASHED_RECOMP_IOS_BUNDLE_ID=com.yourname.unleashedrecomp

cmake --preset ios-xcode-relwithdebinfo \
  -DUNLEASHED_RECOMP_IOS_DEVELOPMENT_TEAM=YOURTEAMID \
  -DUNLEASHED_RECOMP_IOS_BUNDLE_ID=com.yourname.unleashedrecomp \
  -DUNLEASHED_RECOMP_IOS_DETAILED_LOGGING=ON \
  -DUNLEASHED_RECOMP_IOS_SIGNPOSTS=ON

cmake --preset ios-xcode-release \
  -DUNLEASHED_RECOMP_IOS_DEVELOPMENT_TEAM=YOURTEAMID \
  -DUNLEASHED_RECOMP_IOS_BUNDLE_ID=com.yourname.unleashedrecomp
```

Build without signing first when diagnosing compile or link failures:

```bash
cmake --build out/build/ios-xcode-debug --config Debug --target UnleashedRecomp
cmake --build out/build/ios-xcode-relwithdebinfo --config RelWithDebInfo --target UnleashedRecomp
cmake --build out/build/ios-xcode-release --config Release --target UnleashedRecomp
```

In the generated Release target, confirm these effective Xcode settings:

- `Optimization Level` is `Fastest`/`-O3` as generated by the preset.
- Interprocedural optimization is enabled and the linker accepts the selected LTO mode.
- Dead-code stripping and installed-product stripping are enabled.
- Objective-C ARC is enabled for the app target.
- Metal shader source/line tables, verbose iOS logging, BC7 dumping, and PPC bounds checks are disabled.
- The deployment target is iOS 15.0 and the device architecture is arm64.

Debug should retain PPC bounds checking and Metal shader debug information. `RelWithDebInfo` can opt into PPC checking with `-DUNLEASHED_RECOMP_PPC_BOUNDS_CHECK=ON`. Release diagnostics can be enabled explicitly, one option at a time; do not use the diagnostic configuration for performance measurements.

## Functional device matrix

Test on the oldest supported device available and on a recent device. Use a Release build without a debugger for the final pass, in addition to a Debug smoke test.

1. Fresh install from an ISO, an extensionless XContent container, and an extracted directory.
2. Select the same document more than once, cancel the picker, select an invalid file, and select an iCloud item that must download first.
3. Background and foreground while the picker is open, while the installer is hashing/copying, during renderer startup, on a loading screen, and during gameplay.
4. Trigger a simulated memory warning in the simulator and a real high-memory-pressure scenario on device. Confirm the app remains responsive and that cache-trim signposts appear.
5. Rotate or resize on every supported device family and verify drawable-size/swapchain recovery without a black frame loop.
6. Run at least 20 gameplay-to-title-to-gameplay cycles. Record resident memory after each title screen and after each loaded stage.
7. Open the DLC installer from the title screen. On iOS, actions that request an application restart deliberately terminate cleanly; reopen the app manually and verify the requested flow.
8. Lock/unlock the device, switch apps repeatedly, leave the app backgrounded for several minutes, then resume.
9. Verify unsupported BC7 content uses a matching validated override and does not repeatedly perform synchronous dump I/O.
10. Complete a full installation, cancel an installation, and induce insufficient storage. Confirm no `.tmp` files remain and no partially hashed file is treated as installed.

## Instruments plan

Use a `RelWithDebInfo` build with `UNLEASHED_RECOMP_IOS_SIGNPOSTS=ON`. The `Performance` signpost category marks renderer startup, installation, cache trimming, app lifecycle transitions, memory warnings, and restart requests.

- **Time Profiler:** capture cold launch, installer classification, installation, renderer startup, a loading transition, and a return to title. Look for file I/O or texture conversion on the main thread, logging/formatting work, lock contention, and long atomic waits.
- **Allocations:** mark generations at title, stage load, stage exit, and the next title. Repeat at least 20 times. Persistent growth should be attributed by allocation stack before changing cache policy.
- **Leaks:** run both the installer flow and repeated gameplay cycles. Pay particular attention to Objective-C blocks/delegates, Metal drawables, command-buffer completion handlers, SDL Metal views, and security-scoped URLs.
- **VM Tracker:** compare mapped-file regions, thread stacks, Metal allocations, and dirty resident memory at each generation. Confirm guest stacks stay within the configured 8-64 MiB policy and disappear when their threads end.
- **Metal System Trace:** inspect drawable waits, CPU/GPU overlap, in-flight frame depth, command-buffer gaps, pipeline compilation, and waits during swapchain recreation/background recovery.
- **Metal Debugger/API Validation:** run a short Debug capture for resource hazards, invalid load/store actions, out-of-bounds bindings, and drawable lifetime errors. Disable validation for performance runs.
- **Xcode memory graph:** inspect after installer shutdown and after multiple title/gameplay transitions for retained UIKit delegates, `CAMetalLayer`/drawable graphs, completion blocks, and renderer resources.

Record device model, OS version, build configuration/options, debugger attachment, thermal state, stage, resolution scale, frame cap, and whether Metal validation/HUD was enabled. Do not compare memory or timing captures made with materially different settings.

## Diagnostic options

| Option | Default | Purpose |
| --- | --- | --- |
| `UNLEASHED_RECOMP_PPC_BOUNDS_CHECK=AUTO` | Debug only | Detect invalid guest-memory access; use `ON` for a diagnostic RelWithDebInfo build. |
| `UNLEASHED_RECOMP_IOS_DETAILED_LOGGING=OFF` | Off | Enables console plus buffered file logging. Normal Release logs are compiled out. |
| `UNLEASHED_RECOMP_IOS_SIGNPOSTS=OFF` | Off | Adds low-overhead Instruments signposts. |
| `UNLEASHED_RECOMP_IOS_DUMP_BC7=OFF` | Off | Synchronously dumps unsupported BC7 payloads for offline conversion; diagnostic use only. |
| `UNLEASHED_RECOMP_METAL_SHADER_DEBUG_INFO=OFF` | Off | Embeds Metal shader source/line tables for GPU debugging. |
| `UNLEASHED_RECOMP_IOS_GUEST_STACK_MIN_KIB=8192` | 8192 | Minimum native guest-thread stack. |
| `UNLEASHED_RECOMP_IOS_GUEST_STACK_MAX_KIB=65536` | 65536 | Maximum native guest-thread stack. |

## Changes intentionally left for measurement

- Memoryless depth/MSAA attachments, private-storage upload redesigns, and present-timing changes need Metal captures before adoption.
- A forced timeout for renderer/swapchain destruction could avoid an indefinite wait but could also reintroduce callbacks into freed C++ state. Investigate only with a reproducible shutdown hang.
- Permanently suspended guest threads still need a higher-level cancellation and ownership protocol before their joins can safely be made time-bounded.
- True in-process soft restart remains unsupported on iOS. Rebuilding the complete SDL/Metal/guest-thread object graph is riskier than the current clean process exit and manual reopen behavior.
